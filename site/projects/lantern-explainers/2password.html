How 2password finds a secret without showing it to the agent

2password lets a coding agent find and use 1Password secrets without seeing them. Here the agent runs find with two queries, cloud api and the typo databse, against three sample items from 2password’s own tests.

Transcript

Authenticate with: Desktop approvals

  1. find starts by listing item titles

    2password lets a coding agent find and use 1Password secrets without seeing them. Here the agent runs find with two queries, cloud api and the typo databse, against three sample items from 2password’s own tests.

    • Flowchart: 4 nodes, 3 links:
      • Agent → 2password find (travelled);
      • 2password find → op CLI (travelled);
      • Agent;
      • 2password find;
      • op CLI;
      • op CLI → 1Password vault;
      • 1Password vault.
    • Code, 4 lines:
      • 2: Cloud API API_CREDENTIAL Personal (focused);
      • 3: Cloud Login LOGIN Work (focused);
      • 4: Database DATABASE Work (focused);
      • 1: title category vault.
  2. A title matches when it contains every query word

    find lowercases each query and keeps a title only if it contains every word; tags and fields are not searched. Cloud API matches cloud api. No title contains databse, so that query is a miss.

    • Flowchart: 4 nodes, 3 links:
      • Agent → 2password find (travelled);
      • 2password find → op CLI (travelled);
      • Agent;
      • 2password find;
      • op CLI (dimmed);
      • op CLI → 1Password vault (dimmed);
      • 1Password vault (dimmed).
    • Code, 4 lines:
      • 2: Cloud API match no databse (focused);
      • 1: title cloud api databse ;
      • 3: Cloud Login no api no databse ;
      • 4: Database no cloud, api no databse .
  3. A miss returns titles that score at least 0.6

    For a query with no match, find scores each query word against each title word: 1 if one contains the other, otherwise 1 − edit distance ÷ the longer word’s length. A title scores the average of each query word’s best. Database is 1 edit from databse, so it scores 1 − 1/8 = 0.875 and comes back as a suggestion.

    • Flowchart: 4 nodes, 3 links:
      • Agent → 2password find (travelled);
      • 2password find → op CLI (travelled);
      • the rest as in the previous step.
    • Code, 4 lines:
      • 4: Database 0.875 suggested (focused);
      • 1: title closeness to databse ≥ 0.6;
      • 2: Cloud API 0.143 –;
      • 3: Cloud Login 0.000 –.
  4. One op item get fetches the match and the suggestion

    find makes two op calls: item list for titles, then one item get for every item a match or suggestion needs, here Cloud API and Database. 2password’s README says the whole command costs one desktop approval.

    • Sequence diagram: 3 participants, 6 messages:
      • 2password → op CLI: item get for 2 items (marked);
      • Agent;
      • 2password;
      • op CLI;
      • Agent → 2password: find with two queries;
      • 2password → op CLI: item list;
      • op CLI → 2password: ids and titles;
      • op CLI → 2password: item details;
      • 2password → Agent: op:// references.
    • 3 labelled values:
      • Approvals: 1 (marked);
      • op calls: 2;
      • Items fetched: 2.
  5. find prints references and drops the values

    find returns a reference for each match and suggestion, and drops field values while it decodes op’s reply. A reference names a vault, an item and a field: the underlined parts of the Cloud API reference.

    • 3 labelled values:
      • Secret values printed: none (marked);
      • Match for cloud api: op://Personal/Cloud API/credential;
      • Suggestion for databse: op://Work/Database/password.
    • 4 labels:
      • op://Personal/Cloud API/credential;
      • vault;
      • item;
      • field.
  6. op run starts the app with the secret

    run hands op the reference, and op puts the secret into the app’s environment. With desktop approval op holds no token, so it starts the app directly. The app inherits the environment 2password started with, shown here as PATH, plus the secret.

    • Code, 2 lines:
      • 2: → op run -- app (focused);
      • 1: 2password run --env "API_KEY=op://Personal/Cloud API/credential" -- app.
    • Code “op's environment”, 2 lines:
      • 1: PATH=/usr/bin;
      • 2: API_KEY=op://Personal/Cloud API/credential.
    • Code “app's environment”, 2 lines:
      • 1: PATH=/usr/bin;
      • 2: API_KEY=secret-cloud-api.
    • An arrow from op’s environment to the app’s.
