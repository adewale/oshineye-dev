    Start with empty text. Echo replaces it with hello and a newline, and tr uppercases it. The note under each builtin is stdout after it runs: one string handed to the next, with no kernel pipe between them.

      • 1: stdout = "";

      • 3: echo: stdout = args + "\n".
  4. The redirect writes into a new shell

    The redirect stores HELLO in shout.txt and empties stdout. Exec copies the filesystem into a new shell value and returns it, so the original shell on the left still has no files.

    • Flowchart: 4 nodes, 3 links:
      • “"HELLO\n"” beside shout.txt (note);
      • empty stdin;
      • empty stdin → echo hello;
      • echo hello;
      • echo hello → tr a-z A-Z;
      • tr a-z A-Z;
      • tr a-z A-Z → shout.txt;
      • shout.txt.
    • “Original shell”, 2 labelled values:
      • files: none (marked);
      • steps run: 0.
    • “Returned shell”, 4 labelled values:
      • shout.txt: "HELLO\n" (marked);
      • files: shout.txt;
      • steps run: 2;
      • stdout: "".
  5. The model runs echo, tr and cat and refuses ls

    Exec dispatches on the command name: echo, tr and cat each have a branch, and any other name, such as ls, falls through to the last line and throws “Unknown model command”.

    • Flowchart: 4 nodes, 3 links:
      • “echo · tr · cat” beside found: run on values (note);
      • “ls” beside missing: refuse (note);
      • command name → look up the builtin (travelled);
      • look up the builtin → found: run on values (travelled);
      • look up the builtin → missing: refuse (travelled);
      • command name;
      • look up the builtin;
      • found: run on values;
      • missing: refuse.
    • Code, 4 lines:
      • 4: else throw Error("Unknown model command") (focused);
      • 1: if (name === "echo") …
      • 2: else if (name === "tr") …
      • 3: else if (name === "cat") …
  6. cat reads the returned shell

    Cat receives the returned shell, finds shout.txt and prints HELLO. The write is visible only because the caller passed exec’s returned shell to this call.

    • Code, 1 line:
      • 1: exec(returned, [["cat", "shout.txt"]]).
    • “Original shell”, 3 labelled values:
      • files: none;
      • shout.txt: missing;
      • cat stdout: "".
    • “Returned shell”, 3 labelled values:
      • cat stdout: "HELLO\n" (marked);
      • files: shout.txt;
      • shout.txt: "HELLO\n".
  7. The caller holds both shells and can cat either

    Every exec returns the next shell and leaves its input alone. Because the caller holds s0 and s1 at once, it can cat either: s1 prints HELLO and s0 prints nothing.

    • Flowchart: 4 nodes, 3 links:
      • original shell files: none → returned shell files: shout.txt: echo, tr, redirect (travelled);
      • returned shell files: shout.txt → prints HELLO: cat (travelled);
      • original shell files: none;
      • original shell files: none → prints nothing: cat;
      • returned shell files: shout.txt;
      • prints nothing;
      • prints HELLO.
    • Code, 4 lines:

      • 1: s1 = exec(s0, pipeline, "shout.txt").shell;
      • 3: exec(s0, [["cat", "shout.txt"]]).stdout // "";
      • 4: s0.fs // {}.
