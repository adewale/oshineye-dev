Why can int4 and int8 rows take the same space?

Postgres stores a table in pages of 8192 bytes, and every page starts with a 24-byte header, so an empty page has 8168 bytes free. A common way to save space is to declare an integer column int4 rather than int8 (bigint): 4 bytes a value instead of 8. Predict how many more int4 rows than int8 rows fit on one page.

  2. One int4 row takes 36 bytes of the page

    Predict: int8 adds 4 bytes of data. How big is its tuple?

    A row has two allocations: a 4-byte line pointer, which locates it on the page, and the row itself, called a tuple, at the other end: a 23-byte header padded to 24, then the int4, 28 bytes. On a 64-bit build the page gives each tuple a multiple of 8 bytes, here 32, so the row costs 36 bytes, of which 4 are the value.

  3. Answer: none. Both tuples are 32 bytes

    int8 fills the int4 tuple’s padding; a page holds 226 rows of either.

    On a 64-bit build, Postgres gives every tuple a multiple of 8 bytes. The int4 tuple is 28 bytes rounded up to 32, so its last 4 bytes are padding, and int8’s 4 extra bytes take exactly their place. So an int4 row and an int8 row both cost 36 bytes, and a full page holds 226 of either: none more.

Check yourself

  1. Would a row with two int4 columns take more page space than a row with one?

    Show the answer

    No. The first int4 ends at byte 28, and the second fills bytes 28 to 31, the padding one int4 leaves. Both tuples take 32 bytes, so both rows cost 36 and a page holds 226 of either.

  2. Would smallint (int2, 2 bytes) fit more rows on a page than int4?

    Show the answer

    No. Its tuple is 24 + 2 = 26 bytes, which the page rounds up to 32, the same as int4’s 28. Both rows cost 36 bytes and a page holds 226.

  3. With a 15-character text after the integer instead of an 11-character one, does int4 still fit more rows than int8?

    Show the answer

    No. After an int4 the tuple is 44 bytes, rounded up to 48; after an int8 it is 48, already a multiple of 8. Both rows cost 52 bytes, so the saving the 11-character text showed disappears.
