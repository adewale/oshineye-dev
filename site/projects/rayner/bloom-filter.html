Why does a Bloom filter answer “maybe”?

A sign-up form checks each name a person types against the accounts database, one database read per check, and a read for a free name finds nothing. A row of 16 bits kept in memory, all 0 to start, will sit in front of the database and try to answer “not taken” without the read.

    dog’s bits 7, 0 and 1 are filled brown. Bit 1 was already 1 from cat, so it stays 1; its fill shows both names, but the row records only the 1. When a name finds all its bits set, other names may have set every one of them, so the filter can only say maybe.

    No database read: had owl been taken, all three of its bits would be 1.

    Looking up owl uses the same hashes as insertion. If the name had been inserted, its three bits would be set. It finds a 0, so it cannot have been inserted and the database read is skipped. This is an insert-only Bloom filter: taking names sets bits, and nothing clears them.

    Each of wolf’s three bits was set by another name.

    Read the fills: bit 7 from dog, 6 from cat and 1 from both. The filter sees three 1s with no names attached, so it says maybe; the database is asked and answers not taken. Check yourself

  1. In the 32-bit filter, someone also takes eel, whose hashes are 23, 20 and 1. What does the filter now say about wolf, and about owl?

    Show the answer

    wolf gets maybe, a false positive: bit 23 now comes from eel, 22 from cat and 1 from dog and eel. owl still gets definitely not: eel set bit 20, but bits 27 and 13 are still 0.

  2. dog closes its account, and to keep the filter tidy someone sets dog’s three bits back to 0. Then cat, still taken, tries to sign in. What does the filter say about cat at 16 bits, and at 32?

    Show the answer

    At 16 bits, definitely not: bit 1 was shared, so clearing dog’s bits cleared one of cat’s, and the filter turns away a taken name, which a Bloom filter must never do. At 32 bits it still says maybe, but only because dog’s bits there happen to miss cat’s. The row cannot tell which names set a bit, so clearing a departing name’s bits can erase evidence of another name.
